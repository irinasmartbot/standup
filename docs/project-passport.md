# Паспорт проекта

## Общая информация

Название: Moscow StandUp Show Telegram Bot

Назначение: Telegram-бот и админка для бронирования мест на мероприятия Moscow StandUp Show.

Владелец продукта: не зафиксировано в репозитории.

Технический владелец: не зафиксировано в репозитории.

## Git и ветки

Основная рабочая ветка деплоя: `dev`.

Важно: push в `dev` запускает workflow `Deploy dev to VPS` и перезапускает сервис на VPS. Документационные изменения лучше сначала готовить в отдельной ветке и мержить в `dev` только осознанно.

## Локальный запуск

Установка зависимостей:

```bash
pip install -r requirements.txt
```

Запуск бота:

```bash
python bot.py
```

Запуск админки:

```bash
python admin.py
```

Локальная база SQLite создается автоматически в `bookings.db`, если используется локальный режим.

## Окружения

Local: локальный запуск на машине разработчика, переменные берутся из `.env`.

Test/Staging: отдельное окружение не зафиксировано в репозитории.

Production: VPS на Beget, сервисы запускаются через systemd. Детали доступа и секреты не должны храниться в Git.

## Деплой

Деплой настроен через GitHub Actions:

- workflow: `.github/workflows/deploy-dev.yml`;
- триггер: push в ветку `dev`;
- target: `/home/standup/app` на VPS;
- код на сервере приводится к `origin/dev`;
- `.env`, `venv`, `__pycache__` и `*.pyc` сохраняются при `git clean`;
- после обновления выполняется установка зависимостей, подготовка таблиц, импорт событий из Google Sheets и restart `standup-bot`.

Health-check в workflow:

```bash
sudo /usr/bin/systemctl is-active --quiet standup-bot
```

Rollback: не зафиксирован в репозитории.

## База данных

Локально: SQLite.

На сервере: PostgreSQL.

Серверная схема: `bot/db/schema_postgres.sql`.

Документация: `docs/database.md`.

Миграции и сервисные скрипты:

- `scripts/migrate_bookings_from_sqlite.py`;
- `scripts/import_events_from_sheets.py`;
- `scripts/sync_events_hourly.py`;
- `scripts/backup_postgres.sh`.

Любое изменение схемы или массовая операция с данными требует отдельного плана, read-only проверки target, backup/rollback и явного разрешения.

## Внешние системы

- Telegram Bot API: пользовательский бот, бронирования, уведомления и админские сценарии.
- Google Sheets CSV: источник афиши и событий.
- VK: направление розыгрыша и медиа, см. `docs/vk_mvp.md`.
- VPS/systemd: production-запуск бота и вспомогательных сервисов.

По умолчанию внешние системы считаются read-only. Создание, отправка, изменение или удаление требует явного разрешения в рамках конкретной задачи.

## Секреты

Секреты не хранятся в Git.

Локально используются `.env` и `.env.example` без реальных значений.

В GitHub Actions используются GitHub Secrets:

- `VPS_HOST`;
- `VPS_USER`;
- `VPS_SSH_KEY`.

Токены бота, админки, cookies, пароли, приватные ключи, номера телефонов и персональные данные нельзя печатать в логах, коммитах, скриншотах и ответах агента.

## Действия, требующие отдельного разрешения

- Push или merge в `dev`.
- Production-деплой или restart сервисов.
- Изменение workflow деплоя.
- Массовое изменение, удаление или импорт production-данных.
- Изменение схемы базы данных.
- Изменение прав доступа, токенов, секретов или админских ролей.
- Внешняя отправка сообщений, публикаций или мутации в Telegram, Google Sheets, VK или на VPS.
- Force push, reset, clean, checkout с потерей изменений и другие разрушительные Git-действия.

## Проектные ограничения

- Бот обрабатывает персональные данные бронирований, включая имя и телефон.
- Production-деплой связан с веткой `dev`.
- Документация может отставать от кода; при расхождении нужно проверять факты и обновлять документы.
- Не все операционные процедуры зафиксированы: rollback, staging, мониторинг и владельцы решений требуют уточнения.
