## 2026-07-24 — Внедрить регламент работы агентов

Статус: accepted
Владелец решения: Ирина
Связано с: `docs/agent-regulation.md`, `AGENTS.md`, `docs/project-passport.md`

Контекст:
Нужно перенести общий регламент работы AI-агентов в проект так, чтобы не сломать бота, деплой и production.

Подтвержденные факты:
- Проект содержит Telegram-бота, админку, БД, Google Sheets, VK и VPS-контур.
- Push в `dev` запускает deploy workflow и restart сервиса.
- В проекте уже есть `README.md`, `docs/architecture.md`, `docs/database.md`, `docs/vk_mvp.md` и flow-документ.

Решение:
Внедрить регламент как docs-only набор в отдельной ветке: `AGENTS.md`, `docs/00-overview.md`, `docs/project-passport.md`, `docs/agent-regulation.md`, `docs/18-decision-log.md`, `docs/19-current-state.md`, `docs/change-requests.md`.

Последствия и ограничения:
- Код бота, workflow, зависимости и runtime не меняются.
- Merge в `dev` выполняется отдельно и осознанно, потому что он запускает деплой.
- Неизвестные операционные детали помечаются как не зафиксированные, а не выдумываются.

Проверка:
Diff должен содержать только документационные файлы. Код, workflow и `.env` не должны измениться.

### 2026-08-31 22:59 — Розыгрыш не использует max_seats
- Решение: при подтверждении билета розыгрыша (TG 
z_ticket, VK issue_ticket для raffle) лимит мест не проверяется.
- Причина: max_seats относится только к «Проверке»; у BEST/розыгрыша его нет (в таблице часто 0), из-за чего клиенты получали «свободно: 0».
- Статус: принято / внедрено в коде.

### 2026-09-06 — Даты розыгрыша после accept не теряются
- Решение: шаг «проверка подписки + меню дат» после ПРИНЯТЬ держится ссылкой на asyncio-задачу и пишется в `raffle_after_accept`; цикл напоминаний досылает, если фон умер.
- Причина: `asyncio.create_task` без ссылки на Python 3.12 может быть собран GC; рестарт за 3 сек тоже обрывал цепочку. У Natali (`5064600181`) был `raffle_approved` без `raffle_subscribed` / `raffle_sub_failed`.
- Статус: принято / внедрено в коде.

### 2026-09-08 — After-accept: очередь живёт до отправки дат
- Решение: живой воркер сначала шлёт подписку/даты, и только потом удаляет `raffle_after_accept`. Ретрай забирает только записи старше 90 сек (`created_at`), чтобы не украсть задачу у живого воркера. При повторной постановке обновляется и `created_at`.
- Причина: claim до `_continue_after_subscribe_check` + рестарт бота оставляли очередь пустой. У @L_Zaykina (`479828932`) был `raffle_approved` без `raffle_subscribed` / `raffle_sub_failed`, QUEUE пустая, брони нет.
- Статус: принято / внедрено в коде.

### 2026-09-06 — VK билет: проверять photo и удалять текст без картинки
- Решение: после send билета читаем сообщение и требуем `photo`. Нет фото — удаляем это сообщение у клиента и запускаем автоповтор. «Билет по брони» не идёт через `_send_text`.
- Причина: ВК может принять send без вложения; клиент не жалуется. Кэш приложения ВК по-прежнему не видим.
- Статус: принято / внедрено в коде.

### 2026-09-17 — Рассылка: шаблоны, каты и отложенный старт

### 2026-10-05 — Билет не стираем, кроме отмены и переноса даты
- Решение: выданный билет остаётся в чате. Его удаляет только действие клиента: отмена брони или перенос даты, и только если `ticket_message_id` уже есть. Меню, даты, карусель BEST, nav VK/TG билет не трогают. В Telegram то же правило: не стираем фото билета с «Мои брони», розыгрыша и in-place правок. Отмена шоу из админки по-прежнему снимает билет. В VK «В главное меню» с билета розыгрыша не удаляет сообщение, даже если cmid ≠ сохранённый `message_id`.
- Причина: навигация стирала билет, хотя бронь confirmed.
- Статус: принято / усилено записью ниже.

### 2026-10-05 — VK: репост vs подарок на шоу
- Решение: слово «розыгрыш» и ссылка raffle (`#flow=raffle`, `/vk/raffle`, `ref=standup_rozygr`) всегда открывают розыгрыш за репост. С 19:00 до 22:00 МСК «Начать», слово «подарок» и прочий общий вход — подарок на шоу. В другое время подарок на шоу только по ссылке `offline_gift` (`#flow=offline_gift`, `/vk/offline-gift`). Если зашли по `offline_gift`, кнопка «за репост» / raffle в mini app всё равно открывает подарок на шоу. Ссылки брони / platka / резиденты не перехватываем.
- Причина: онлайн-розыгрыш за репост и подарок в зале должны открываться разными входами; вечером общий старт — зал, днём зал только по своей ссылке. Ссылка зала не должна ломаться, если человек жмёт соседнюю кнопку.
- Статус: принято / выкладка на `main`.

### 2026-10-07 — Рассылка: Telegram и VK параллельно
- Решение: два воркера (`telegram` / `vkontakte`). Каждый берёт свою кампанию или свою половину канала «Оба». Получатели по-прежнему `FOR UPDATE SKIP LOCKED`, кампания `done` только когда pending нет ни у одного канала.
- Причина: Telegram ждал окончания всей VK-рассылки.
- Статус: принято / выкладка на `main`. Два воркера не гоняют `ensure_mailing_tables` параллельно: схема один раз под lock, иначе deadlock на `ALTER TABLE users`.

### 2026-10-10 — Telegram API через точечный SSH relay
- Решение: добавить опциональные `TELEGRAM_RELAY_HOST`, `TELEGRAM_RELAY_PORT`, `TELEGRAM_RELAY_LIMIT`. Пустой host оставляет прямое подключение. При включении только обращения к `api.telegram.org:443` резолвятся в локальный SSH-туннель, без `HTTPS_PROXY` и без отключения TLS-проверки.
- Причина: второму Telegram-боту нужен доступ к Telegram API через зарубежный VPS, при этом бот, база и файлы остаются на текущем сервере.
- Статус: реализовано локально в ветке `feat/telegram-api-relay`; туннель на сервере бота `31.128.47.4` проверен curl и restart сервиса; приложение, `getMe/getWebhookInfo`, меню владельца, изображение и влияние на зарубежный VPS ещё не проверены.
