# VK Mini App: создание, настройка и модерация

Документ описывает, как с нуля создать VK Mini App, подключить его к проекту, подготовить к модерации VK и безопасно передать на проверку.

Команды ниже даны в двух вариантах:

- **универсальный шаблон** — его может использовать другой специалист в своём проекте;
- **пример нашего проекта** — настройки `go.moscowstandupshow.ru`, `/home/standup/app`, `standup-admin`.

Если у проекта другой сервер, домен, путь или systemd-сервис, нужно заменить эти значения на свои.

## 0. Быстрый старт для агента/разработчика

Если эту инструкцию получает другой специалист или AI-агент, сначала нужно заполнить входные данные проекта. Без них агент сможет подготовить код, но не сможет корректно настроить кабинет VK и сервер.

### 0.1. Данные, которые нужно дать агенту

```text
PROJECT_NAME=<название проекта>
VK_COMMUNITY_NAME=<название VK-сообщества>
VK_COMMUNITY_LINK=https://vk.ru/<screen_name>
VK_GROUP_ID=<id сообщества без минуса>

MINI_APP_DOMAIN=<домен, где будет доступен mini app>
MINI_APP_URL=https://<домен>/vk-mini
MINI_APP_START_URL=https://<домен>/vk-mini/start/booking

SERVER_HOST=<user>@<server_ip_or_host>
PROJECT_PATH=<путь к проекту на сервере>
BACKEND_SERVICE=<имя systemd-сервиса backend>

BACKEND_STACK=<python/aiohttp | node/express | php | другое>
REPO_PATH=<локальный путь к проекту>
DEPLOY_METHOD=<git pull + systemctl | CI/CD | docker | другое>

VK_MINI_APP_ID=<id из кабинета VK>
VK_MINI_APP_SECRET=<защищённый ключ, передавать только безопасным способом>
VK_GROUP_TOKEN=<токен сообщества, передавать только безопасным способом>
```

Если каких-то значений ещё нет, задача агента должна быть разделена на два этапа:

1. Подготовить код, список env и чек-лист настроек.
2. После получения `VK_MINI_APP_ID`, `VK_MINI_APP_SECRET`, `VK_GROUP_TOKEN` прописать env, задеплоить и протестировать.

### 0.2. Что агент должен сделать в коде

Минимальный результат:

- создать публичный route `GET /vk-mini`;
- создать route `GET /vk-mini/start/booking`, который открывает нужный сценарий;
- создать API `POST /vk-mini/entry`;
- на frontend вызвать `VKWebAppInit`;
- получить launch-параметры через URL или `VKWebAppGetLaunchParams`;
- запросить разрешение на сообщения через `VKWebAppAllowMessagesFromGroup`;
- отправить launch-параметры на backend;
- на backend проверить подпись `sign` через `VK_MINI_APP_SECRET`;
- достать `vk_user_id`;
- отправить пользователю нейтральное сообщение через `VK_GROUP_TOKEN`;
- защититься от повторной отправки при двойном клике;
- показать понятный статус пользователю;
- добавить запасную кнопку открытия диалога VK.

### 0.3. Что агент не должен делать

- Не коммитить `.env`.
- Не вставлять `VK_MINI_APP_SECRET` во frontend.
- Не писать реальные токены в markdown, логи или комментарии.
- Не включать Long Poll-бота на боевом сообществе, если там уже работает Salebot/другой бот.
- Не добавлять розыгрыши, платежи и сбор персональных данных в первый модерационный сценарий без необходимости.
- Не использовать значения нашего проекта как обязательные: `go.moscowstandupshow.ru`, `/home/standup/app`, `standup-admin` — это только пример.

### 0.4. Критерии готовности

Задача готова, если:

- `https://<домен>/vk-mini` открывается внутри VK;
- `https://<домен>/vk-mini/start/booking` открывает booking-сценарий;
- пользователь может разрешить сообщения от сообщества;
- backend принимает `POST /vk-mini/entry` только с валидной подписью VK;
- сообщение приходит пользователю в личку VK;
- повторный клик не отправляет много одинаковых сообщений подряд;
- на Android и десктопе есть понятный способ открыть диалог VK;
- в интерфейсе нет debug-текстов и неготовых веток;
- в репозитории нет секретов.

### 0.5. Короткий промпт для AI-агента коллеги

```text
Прочитай docs/vk_mini_app_moderation_guide.md и реализуй VK Mini App для моего проекта.

Используй универсальные шаблоны, не значения Moscow StandUp Show.
Сначала проверь, какие данные проекта у тебя есть: домен, VK_GROUP_ID, VK_MINI_APP_ID, VK_MINI_APP_SECRET, VK_GROUP_TOKEN, путь сервера, имя backend-сервиса.
Если секретов нет, подготовь код и список env, но не выдумывай значения.

Нужно получить:
- GET /vk-mini
- GET /vk-mini/start/booking
- POST /vk-mini/entry
- проверку подписи VK launch params через VK_MINI_APP_SECRET
- запрос VKWebAppAllowMessagesFromGroup
- отправку нейтрального сообщения пользователю через VK_GROUP_TOKEN
- fallback-кнопку открытия диалога VK
- чек-лист тестирования перед модерацией

Не коммить .env, не вставляй секреты во frontend, не запускай Long Poll-бота на боевом сообществе, если там уже работает другой бот.
```

## 1. Что должно получиться

Mini App открывается внутри VK, показывает простой сценарий, получает подписанные параметры запуска от VK, запрашивает разрешение на сообщения сообщества и отправляет пользователю нейтральное сообщение в личку от имени сообщества.

Для модерации лучше показывать минимальный понятный сценарий:

- один основной экран;
- одна основная кнопка;
- нейтральный текст без спорных обещаний, розыгрышей, платежей и агрессивной рекламы;
- понятное продолжение в личных сообщениях VK;
- без лишних тестовых функций и скрытых админских возможностей.

## 2. Где создаётся Mini App

Создание и настройка делаются в кабинете VK для разработчиков:

```text
https://vk.com/apps?act=manage
```

Или через меню VK:

1. Открыть VK под аккаунтом владельца/ответственного за приложение.
2. Перейти в раздел приложений для разработчиков.
3. Создать новое приложение.
4. Выбрать тип приложения, связанный с VK Mini Apps / встраиваемым веб-приложением.

Важно: приложение лучше создавать на аккаунте клиента/владельца проекта, а не на личном аккаунте подрядчика. Если приложение создаёт подрядчик, заранее договориться, кто будет владельцем, кто сможет проходить модерацию и кто будет иметь доступ к ключам.

## 3. Что подготовить заранее

Перед созданием приложения должны быть готовы:

- VK-сообщество, от имени которого будут отправляться сообщения.
- Включённые сообщения сообщества.
- HTTPS-домен, на котором доступен mini app.
- Рабочий backend-эндпоинт для mini app.
- Страница, которая корректно открывается внутри VK WebView.
- Доступ к серверу/деплою.
- Понимание, какой сценарий показываем модератору.

Универсальный шаблон:

```text
Домен: <your-mini-app-domain>
Mini App: https://<your-mini-app-domain>/vk-mini
Стартовый сценарий: https://<your-mini-app-domain>/vk-mini/start/booking
```

Пример нашего проекта:

```text
Домен: go.moscowstandupshow.ru
Mini App: https://go.moscowstandupshow.ru/vk-mini
Старт booking-сценария: https://go.moscowstandupshow.ru/vk-mini/start/booking
```

## 4. Настройки в кабинете VK

В кабинете приложения нужно заполнить базовые данные.

### Название

Название должно быть нейтральным и соответствовать тому, что видит пользователь.

Пример:

```text
Moscow StandUp Show
```

Не стоит использовать временные названия вида `test`, `bot`, `debug`, `moderation app`, если приложение отправляется на модерацию.

### Иконка и оформление

Загрузить чистую иконку бренда без мелкого текста. Лучше квадратная, контрастная, без спорных изображений и без обещаний вроде "бесплатно", "выигрыш", "скидка 100%".

### Описание

Описание должно объяснять сценарий простыми словами.

Пример нейтрального текста:

```text
Мини-приложение помогает гостю продолжить общение с сообществом Moscow StandUp Show в личных сообщениях VK. Пользователь выбирает действие, разрешает сообщения от сообщества и получает информацию в диалоге VK.
```

Для модерации лучше не писать:

- "гарантированный подарок";
- "розыгрыш без условий";
- "моментальная бронь без подтверждения";
- "скидка только сейчас";
- любые обещания, которые не подтверждаются в интерфейсе.

### Базовый домен

Указать домен без пути:

Универсальный шаблон:

```text
<your-mini-app-domain>
```

Пример нашего проекта:

```text
go.moscowstandupshow.ru
```

Домен должен открываться по HTTPS с валидным сертификатом. На Android VK WebView особенно чувствителен к проблемам SSL.

### URL приложения

Указать рабочий URL mini app:

Универсальный шаблон:

```text
https://<your-mini-app-domain>/vk-mini
```

Пример нашего проекта:

```text
https://go.moscowstandupshow.ru/vk-mini
```

Если нужен конкретный сценарий для модерации, можно использовать стартовый URL:

Универсальный шаблон:

```text
https://<your-mini-app-domain>/vk-mini/start/booking
```

Пример нашего проекта:

```text
https://go.moscowstandupshow.ru/vk-mini/start/booking
```

### Привязка к сообществу

Привязать приложение к нужному VK-сообществу. Сообщество должно быть тем же, от имени которого backend будет отправлять сообщения пользователю.

Для боевого проекта важно не перепутать:

- `VK_GROUP_ID` — ID сообщества без минуса.
- В ссылках на диалог VK используется `write-{GROUP_ID}` или `vk.me/<screen_name>`.
- В `peer_id` для сообщений сообщество может отображаться с минусом, но в env обычно хранится ID без минуса.

## 5. Где брать ключи и параметры

### `VK_MINI_APP_ID`

Это ID приложения в кабинете VK.

Где взять:

1. Открыть приложение в кабинете VK.
2. Найти ID приложения в настройках или в URL.
3. Скопировать числовое значение.

Пример:

```env
VK_MINI_APP_ID=54704296
```

ID приложения не является секретом, но лучше всё равно хранить его в env, чтобы не зашивать в код.

### `VK_MINI_APP_SECRET`

Это защищённый ключ приложения. Он нужен backend'у, чтобы проверять подпись launch-параметров VK (`sign`) и понимать, что запрос действительно пришёл из VK Mini App.

Где взять:

1. Открыть приложение в кабинете VK.
2. Перейти в настройки / ключи / защищённый ключ.
3. Скопировать значение.
4. Сохранить только в `.env` на сервере или в защищённом хранилище секретов.

Нельзя:

- коммитить `VK_MINI_APP_SECRET` в git;
- отправлять ключ в чат без необходимости;
- вставлять ключ во frontend;
- показывать ключ в скриншотах для модерации.

Если ключ попал в публичное место, его нужно перевыпустить в кабинете VK и обновить на сервере.

### `VK_GROUP_ID`

ID сообщества, от имени которого пишем пользователю.

Где взять:

- в настройках сообщества;
- через URL вида `vk.com/club123456789`;
- через API/админку сообщества.

В env указывать без минуса:

```env
VK_GROUP_ID=123456789
```

### `VK_GROUP_TOKEN`

Токен сообщества для отправки сообщений через VK API.

Где взять:

1. Открыть настройки сообщества.
2. Перейти в раздел работы с API / ключи доступа.
3. Создать ключ доступа сообщества.
4. Выдать минимально нужные права.

Для mini app, который отправляет сообщение в личку, обычно нужны права на сообщения сообщества. Если проект дополнительно загружает изображения, может понадобиться доступ к фото/загрузке медиа, но для простого текстового сценария это не обязательно.

Нельзя:

- включать Long Poll на боевом токене, если параллельно продолжает работать Salebot или другой бот;
- хранить токен в коде;
- коммитить токен;
- давать токен подрядчикам без ограничения доступа.

Если Salebot должен временно остаться на фоне, можно использовать боевой `VK_GROUP_TOKEN` только в admin/backend для отправки первого сообщения, но не запускать наш VK Long Poll-бот на боевом сообществе.

### `VK_OPENAPI_APP_ID`

Это отдельный ID для веб-лендингов с виджетом `AllowMessagesFromCommunity`. Для самого VK Mini App он не обязателен, если mini app использует VK Bridge.

В нашем проекте он используется для публичных страниц `/vk/booking`, `/vk/raffle`, `/vk/offline-gift`, а mini app использует:

```env
VK_MINI_APP_ID
VK_MINI_APP_SECRET
VK_GROUP_ID
VK_GROUP_TOKEN
```

## 6. Env на сервере

На сервере переменные нужно добавлять в `.env` того backend-сервиса, который отдаёт mini app и обрабатывает `POST /vk-mini/entry`.

Универсальный шаблон:

```text
<project_path>/.env
```

Примеры:

```text
/var/www/my-project/.env
/home/app/current/.env
```

В нашем проекте mini app обслуживает `standup-admin`, поэтому переменные лежат здесь:

```text
/home/standup/app/.env
```

Минимальный набор:

```env
VK_ENABLED=1
VK_GROUP_ID=<id_сообщества_без_минуса>
VK_GROUP_TOKEN=<токен_сообщества>
VK_COMMUNITY_LINK=https://vk.ru/<screen_name>
VK_MINI_APP_ID=<id_mini_app>
VK_MINI_APP_SECRET=<защищённый_ключ_mini_app>
```

Если используются веб-лендинги с OpenAPI-виджетом:

```env
VK_OPENAPI_APP_ID=<id_web_app>
```

После изменения env на сервере нужно перезапустить backend-сервис.

Универсальный шаблон:

```bash
ssh <user>@<server_ip_or_host>
cd <project_path>
sudo systemctl restart <backend_service_name>
```

Если код обновлялся из git:

```bash
ssh <user>@<server_ip_or_host>
cd <project_path>
git pull
sudo systemctl restart <backend_service_name>
```

Пример нашего проекта:

```bash
ssh standup@31.128.47.4
cd /home/standup/app
git pull
sudo systemctl restart standup-admin
```

## 7. Backend-логика mini app

В нашем проекте mini app находится в:

```text
bot/admin/vk_entry.py
```

Основные маршруты:

```text
GET  /vk-mini
GET  /vk-mini/start/booking
GET  /vk-mini/start/raffle
GET  /vk-mini/start/offline_gift
POST /vk-mini/entry
```

Текущий модерационный вариант показывает только booking-сценарий:

```python
MINI_APP_VISIBLE_FLOWS = ("booking",)
```

Это сделано специально, чтобы модератор видел один понятный сценарий без лишних веток.

## 8. Проверка подписи VK

Mini App получает launch-параметры от VK. В них есть:

- `vk_user_id`;
- `vk_app_id`;
- `vk_platform`;
- другие `vk_*` параметры;
- `sign`.

Backend должен проверить подпись через `VK_MINI_APP_SECRET`. Это защищает `/vk-mini/entry` от прямых запросов извне.

Принцип:

1. Frontend собирает launch-параметры из URL или `VKWebAppGetLaunchParams`.
2. Отправляет их на backend в `POST /vk-mini/entry`.
3. Backend проверяет `sign`.
4. Backend достаёт `vk_user_id`.
5. Backend отправляет сообщение пользователю от имени сообщества.

Если `sign` не проверять, любой человек сможет дернуть API и отправлять сообщения от имени проекта тем пользователям, которые дали разрешение.

## 9. Frontend-логика mini app

Mini app должен:

1. Вызвать `VKWebAppInit`.
2. Получить launch-параметры через URL или `VKWebAppGetLaunchParams`.
3. Показать понятную кнопку.
4. Запросить разрешение на сообщения через `VKWebAppAllowMessagesFromGroup`.
5. Отправить `POST /vk-mini/entry`.
6. Показать понятный статус.
7. По возможности открыть диалог VK.

Методы VK Bridge, которые используются:

```js
VKWebAppInit
VKWebAppGetLaunchParams
VKWebAppAllowMessagesFromGroup
VKWebAppOpenURL
VKWebAppClose
```

Для Android важно тестировать отдельно. Клиент VK может по-разному обрабатывать автопереходы в диалог: иногда `vk://` срабатывает, иногда нужен явный тап пользователя. Поэтому в интерфейсе всегда должна оставаться запасная кнопка "Открыть диалог VK".

## 10. Наш пример mini app для модерации

### Цель

Показать модератору VK простой сценарий: пользователь открывает mini app, разрешает сообщения от сообщества и получает нейтральное сообщение в личку VK.

### URL

```text
https://go.moscowstandupshow.ru/vk-mini
https://go.moscowstandupshow.ru/vk-mini/start/booking
```

### Видимый сценарий

Временно показываем только:

```text
booking
```

Не показываем в mini app для модерации:

- розыгрыш;
- подарок;
- сложные ветки;
- спорные обещания;
- админские действия.

### Текст на экране

Нейтральный вариант:

```text
Забронируйте места на шоу — продолжение в личке VK.
```

Кнопка:

```text
Забронировать места
```

### Сообщение в личку

Для модерации лучше отправлять мягкий нейтральный текст без агрессивной продажи:

```text
Привет!

Мы поможем забронировать места на шоу Moscow StandUp Show.

Напишите, какой формат вам интересен — менеджер пришлёт варианты.
```

В нашем коде временный текст находится в `BOOKING_ENTRY_TEXT`. В боевом режиме можно вернуть полноценные кнопки форматов, но на модерацию лучше отправлять простой сценарий.

### Почему без кнопок форматов

На время модерации и параллельной работы с Salebot лучше не показывать сложные cmd-кнопки, чтобы:

- модератор не попал в неготовую ветку;
- Salebot и новый VK-бот не спорили за пользователя;
- интерфейс выглядел как законченный простой сценарий;
- не было лишних вопросов по розыгрышам/подаркам.

## 11. Как подготовиться к модерации

### Проверить доступность URL

Открыть:

```text
https://go.moscowstandupshow.ru/vk-mini
```

Должно открываться без логина в админку, без 500, без редиректа на `/admin`.

### Проверить HTTPS

Сертификат должен быть валидным. Особенно важно для Android VK.

Проверить:

- домен открывается в обычном браузере;
- нет предупреждения о сертификате;
- нет смешанного контента `http://`;
- все внешние ресурсы грузятся по HTTPS.

### Проверить env

На сервере.

Универсальный шаблон:

```bash
ssh <user>@<server_ip_or_host>
```

## 13. Риски для модерации VK

### Слишком сложный сценарий

Если mini app сразу показывает несколько веток, розыгрыш, подарок, бронирование и внешние ссылки, модератору сложнее понять, что проверять. Лучше отправлять один чистый сценарий.

### Розыгрыши и подарки

Розыгрыши могут вызвать дополнительные вопросы:

- какие условия участия;
- где правила;
- как выбирается победитель;
- есть ли ограничения;
- нет ли азартной механики.

Если розыгрыш не обязателен для модерации mini app, лучше временно скрыть его.

### Обещания и продажи

Не использовать формулировки:

- "гарантированно";
- "выиграете";
- "бесплатно без условий";
- "только сейчас";
- "последний шанс".

### Сбор персональных данных

Если mini app собирает телефон, имя, email или другие данные, нужна понятная политика и объяснение. Для модерации проще не собирать ничего в mini app, а продолжать диалог в сообщениях VK.

### Платежи

Если внутри mini app есть оплата, модерация будет сложнее. Для первого прохождения лучше не включать оплату, если она не нужна.

### Неработающие внешние ссылки

Все ссылки должны открываться:

- в VK WebView;
- на Android;
- на iOS;
- на десктопе.

Если ссылка может не открыться автоматически, должна быть запасная кнопка.

### Конфликт ботов

Если одновременно работают Salebot и свой Long Poll-бот на одном сообществе, они могут отвечать параллельно. На время модерации лучше:

- оставить Salebot на боевом чате;
- использовать свой backend только для отправки первого сообщения;
- не запускать свой Long Poll-бот на боевом токене.

## 14. Что лучше не делать перед модерацией

Не стоит:

- менять токены в последний момент без теста;
- отправлять на модерацию URL, который доступен только с авторизацией;
- показывать тестовые данные и debug-тексты;
- оставлять кнопки, ведущие в неготовые ветки;
- использовать реальные клиентские переписки в скриншотах;
- включать Long Poll-бота на боевом сообществе, если Salebot ещё работает;
- коммитить `.env`;
- вставлять `VK_MINI_APP_SECRET` во frontend;
- проверять подпись только на клиенте;
- полагаться только на автопереход в диалог без запасной кнопки.

## 16. Рекомендованная структура реализации для другого проекта

Минимальная архитектура:

```text
backend
  GET  /vk-mini
  GET  /vk-mini/start/<flow>
  POST /vk-mini/entry

frontend inside /vk-mini
  VKWebAppInit
  VKWebAppGetLaunchParams
  VKWebAppAllowMessagesFromGroup
  POST /vk-mini/entry
  VKWebAppOpenURL fallback

env
  VK_GROUP_ID
  VK_GROUP_TOKEN
  VK_MINI_APP_ID
  VK_MINI_APP_SECRET
  VK_COMMUNITY_LINK
```

### API-контракт

`GET /vk-mini`

Возвращает HTML/SPA mini app. Страница должна работать внутри VK WebView и не требовать авторизации в админке.

`GET /vk-mini/start/booking`

Возвращает тот же mini app, но сразу выбирает booking-сценарий. Это удобно для модерации и для прямой ссылки из кабинета VK.

`POST /vk-mini/entry`

Запрос:

```json
{
  "flow": "booking",
  "launch_params": "?vk_user_id=123&vk_app_id=456&vk_platform=mobile_android&sign=..."
}
```

Ответ при успехе:

```json
{
  "ok": true
}
```

Ответ при повторной быстрой отправке:

```json
{
  "ok": true,
  "ok_soft": true,
  "error": "Сообщение уже отправляли — проверьте личку VK."
}
```

Ответ при ошибке:

```json
{
  "ok": false,
  "error": "Нет подписанных параметров запуска VK."
}
```

Backend-правила:

- принимать только известные `flow`;
- проверять `sign` до отправки сообщения;
- брать `vk_user_id` только из проверенных launch-параметров;
- не доверять `vk_user_id`, присланному отдельным полем без подписи;
- иметь cooldown от повторной отправки;
- логировать техническую ошибку без токенов и персональных данных.

Backend должен:

- отдавать HTML mini app;
- валидировать `sign`;
- доставать `vk_user_id`;
- ограничивать частоту повторных отправок;
- отправлять сообщение через VK API;
- возвращать понятные ошибки.

Frontend должен:

- не хранить секреты;
- не доверять себе в вопросах безопасности;
- передавать launch-параметры на backend;
- показывать понятный статус;
- иметь fallback-кнопку для открытия диалога.
